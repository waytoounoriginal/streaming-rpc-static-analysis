\section{Related Work}
\label{ch:related-work}

Protocol checking brings together behavioral type theory, typestate analysis, and API misuse detection. Reviewing key calculi and Java, C/MPI, and C++ verifiers (1986--2026), we compare systems across four criteria: (1)~\emph{how protocols are specified}, (2)~\emph{how endpoint code is checked}, (3)~\emph{annotation cost and false-positive triage}, and (4)~\emph{whether distributed deadlock freedom is proved}. Our work combines Protobuf custom-option session contracts, Clang AST checking on unmodified synchronous C++ gRPC streams, and syntactic tracking of \texttt{oneof} and field-presence calls.

\subsection{Theoretical Foundations: Session Types, Subtyping, and Typestate}
\label{sec:rw-foundations}

\paragraph{Binary Session Types and gRPC Streams.}
Honda, Vasconcelos, and Kubo~\cite{honda-v-k-1998} structured two-party protocols with send ($!T; S$), receive ($?T; S$), internal choice ($\oplus$), external branching ($\&$), and recursion ($\mu X. S$). Yoshida and Vasconcelos~\cite{yoshida-vasconcelos-2007} proved Subject Reduction and formalized endpoint duality ($\overline{S}$), while Honda, Yoshida, and Carbone~\cite{honda-yoshida-carbone-2008} extended the model to Multiparty Session Types (MPST) for $N \ge 3$ peers. Because each gRPC streaming RPC runs over one HTTP/2 stream between one client stub and one server handler, binary session types compiled to deterministic finite-state machines (DFSMs) as in Scribble~\cite{honda-et-al-2011} capture each endpoint's allowed call sequences---allowing concurrent read and write progress rather than strict turn-taking---and match the peer contract via $\overline{S}$. Unlike global MPST progress~\cite{honda-yoshida-carbone-2008}, checking one endpoint locally does not prove distributed deadlock freedom. We focus on synchronous C++ streams (\texttt{ClientReaderWriter}, \texttt{ServerReaderWriter}, and unidirectional variants), which remain common in Apache Arrow Flight, BuildBox, and WeNet.

\paragraph{Termination, Refinements, and Typestate.}
Gay and Hole~\cite{gay-hole-2005} introduced coinductive subtyping for safe normal protocol evolution. By contrast, gRPC stream failures (\texttt{Write()} or \texttt{Read()} returning \texttt{false}), cancellations, and server non-\texttt{OK} status returns are early abort exits modeled separately in Section~\ref{ch:experimental-modeling}. For message data constraints, Ueno and Das~\cite{ueno-das-2026} infer arithmetic refinements; our Level~2 rules instead track syntactic Protobuf \texttt{oneof} choices and explicit-presence setters (\texttt{set\_*}, \texttt{mutable\_*}, \texttt{clear\_*}). For imperative code, Strom and Yemini~\cite{strom-yemini-1986} introduced typestate over control-flow graphs, Nielson and Nielson~\cite{nielson-nielson-1999} defined sequential effect systems, Orchard and Yoshida~\cite{orchard-yoshida-2016} linked session types to effects, and Pradel et al.~\cite{pradel-et-al-2012} showed how false-positive triage shapes real-world API checkers ($41$ bugs and code smells at $51\%$ precision).

\subsection{Existing Protocol Verification Tools in Java, C, and C++}
\label{sec:rw-systems}

We compare five representative protocol checkers (summarized in Table~\ref{tab:related-work-comparison}):
\begin{itemize}
    \item \textbf{Mungo / StMungo~\cite{kouzapas-et-al-2016}:} Translates Scribble specs into Java \texttt{@Typestate} annotations and generated skeleton classes, branching on \texttt{enum} return values (evaluated on an SMTP client). We reuse DFSM lowering and \texttt{bool} return branching (\texttt{Read(\&msg)}), but check standard \texttt{grpc::} classes directly without generating skeleton wrappers.
    \item \textbf{Hu \& Yoshida~\cite{hu-yoshida-2016}:} Generates state-indexed Java fluent channel classes ($C_{q_1} \to C_{q_2}$) with lightweight runtime linearity checks. Because C++ gRPC exposes every method on a single fixed stream class in all states, checking existing callers requires external contracts instead of splitting API types.
    \item \textbf{Session C~\cite{ng-yoshida-honda-2012-cc, ng-et-al-2012}:} Checks C/MPI and FPGA code against multiparty Scribble trees for distributed deadlock freedom, requiring programs to use custom \texttt{libsess} calls; we keep AST checking while leaving \texttt{grpc::} code unchanged.
    \item \textbf{Marques et al.~\cite{marques-et-al-2013}:} Checks \emph{unmodified} C calls to \texttt{mpi.h} using ghost contracts in Microsoft VCC/SMT ($4$ MPI programs, $256$--$429$~LOC). It proves stronger buffer and rank bounds at $3.9\%$--$4.7\%$ manual annotations and $3.7$--$11.4\,\mathrm{s}$ solver times; we trade memory/rank proofs for $0$ inline C++ annotations.
    \item \textbf{Coconut~\cite{alsubhi-et-al-2025}:} Encodes protocols in C++20 templates verified by a GCC-13 GIMPLE pass with runtime monitoring for aliasing pointers (cutting \emph{PillBox} NLOC from $389$ to $129$ and cyclomatic complexity from $90$ to $22$). We avoid C++20 rewrites, early IR lowering, and runtime checks, though Coconut's interprocedural summaries and alias tracking handle multi-function code better than our intraprocedural walker.
\end{itemize}

\subsection{Comparative Synthesis and Positioning Hypotheses}
\label{sec:rw-comparison}

Table~\ref{tab:related-work-comparison} separates external specification effort, source edits, custom wrapper requirements, inline C/C++ annotation density ($0/100$~LOC inline vs.\ $1$--$2$ external \texttt{.proto} option lines per custom RPC), and static vs.\ runtime checking. Section~\ref{ch:case-study} tests three hypotheses:
\begin{itemize}
    \item \textbf{H1 (Low Intrusiveness):} External Protobuf options verify synchronous C++ gRPC endpoints with $0$ C++ edits, $0$ inline annotations per $100$~LOC ($1$--$2$ option lines per custom RPC; $0$ for default Level~1), and zero runtime overhead.
    \item \textbf{H2 (Controlled Accuracy and Speed):} On controlled handlers and unit suites covering Level~1 ordering and Level~2 payloads, our AST checker catches sequence, variant, loop, and early-return bugs while adding $R_1 < 1\%$ to Clang frontend time.
    \item \textbf{H3 (Open-Source False Positives and Candidate Review):} When run without repo-specific heuristics on unmodified OSS code (Section~\ref{sec:oss-baseline}), intraprocedural checking reveals clear false-positive causes on safe controls (helper wrappers, background threads, member flags---motivating Coconut-style summaries~\cite{alsubhi-et-al-2025}) and reviews Category~D candidates qualitatively without estimating open-source Recall when confirmed upstream bugs are unavailable.
\end{itemize}
