\section{Related Work}
\label{ch:related-work}

Protocol checking brings together behavioral type theory, typestate analysis, and API misuse detection. Reviewing key calculi and Java, C/MPI, and C++ protocol checkers (1986--2026), we compare systems across four criteria: (1)~\emph{how protocols are specified}, (2)~\emph{how endpoint code is checked}, (3)~\emph{where annotation burden sits and how false positives are triaged}, and (4)~\emph{whether distributed deadlock freedom is proved}. Our tool uses Protobuf custom-option session contracts and Clang AST checking as a static bug finder for unmodified synchronous C++ gRPC streams, paired with syntactic tracking of \texttt{oneof} and field-presence calls.

\subsection{Theoretical Foundations: Session Types, Subtyping, and Typestate}
\label{sec:rw-foundations}

\paragraph{Binary Session Types and gRPC Streams.}
Honda, Vasconcelos, and Kubo~\cite{honda-v-k-1998} structured two-party protocols with send ($!T; S$), receive ($?T; S$), internal choice ($\oplus$), external branching ($\&$), and recursion ($\mu X. S$). Yoshida and Vasconcelos~\cite{yoshida-vasconcelos-2007} proved Subject Reduction and formalized endpoint duality ($\overline{S}$), while Honda, Yoshida, and Carbone~\cite{honda-yoshida-carbone-2008} generalized the calculus to Multiparty Session Types (MPST) for $N \ge 3$ peers. Because each gRPC streaming RPC runs over one HTTP/2 stream between one client stub and one server handler, we use binary session types strictly as a specification syntax and duality rule ($\overline{S}$): compiling a spec into deterministic finite-state machines (DFSMs) as in Scribble~\cite{honda-et-al-2011} captures an endpoint's legal call sequences and allows concurrent read and write progress rather than strict turn-taking. Unlike MPST global type systems~\cite{honda-yoshida-carbone-2008}, checking a single C++ endpoint locally is not a sound proof of distributed deadlock freedom across peers. We focus on synchronous C++ streams (\texttt{ClientReaderWriter}, \texttt{ServerReaderWriter}, and unidirectional variants), which remain common in Apache Arrow Flight, BuildBox, and WeNet.

\paragraph{Termination, Refinements, and Typestate.}
Gay and Hole~\cite{gay-hole-2005} introduced coinductive subtyping for safe normal protocol evolution. By contrast, gRPC stream failures (\texttt{Write()} or \texttt{Read()} returning \texttt{false}), cancellations, and server non-\texttt{OK} status returns act as early abort exits, which we model separately in Section~\ref{ch:experimental-modeling}. For message data constraints, Ueno and Das~\cite{ueno-das-2026} infer arithmetic refinements, whereas our Level~2 rules track syntactic Protobuf \texttt{oneof} choices and explicit-presence setters (\texttt{set\_*}, \texttt{mutable\_*}, \texttt{clear\_*}). For imperative languages, Strom and Yemini~\cite{strom-yemini-1986} tracked typestate along control-flow graphs, Nielson and Nielson~\cite{nielson-nielson-1999} introduced sequential effect systems, and Orchard and Yoshida~\cite{orchard-yoshida-2016} connected session types to effects. In empirical evaluation, Pradel et al.~\cite{pradel-et-al-2012} showed how false-positive triage shapes practical API checkers ($26$ bugs and $15$ code smells out of $81$ warnings, $51\%$ precision).

\subsection{Existing Protocol-Checking Tools in Java, C, C++, Rust, and Go}
\label{sec:rw-systems}

We compare five protocol checkers in Table~\ref{tab:related-work-comparison} alongside industrial C/C++ resource checkers and single-stream tools in Rust and Go:
\begin{itemize}
    \item \textbf{Mungo / StMungo~\cite{kouzapas-et-al-2016}:} Translates Scribble specs into Java \texttt{@Typestate} annotations and generated skeleton classes, branching on \texttt{enum} return values (evaluated on an SMTP client). We reuse DFSM lowering and \texttt{bool} return branching (\texttt{Read(\&msg)}), but check standard \texttt{grpc::} classes directly without generating skeleton wrappers.
    \item \textbf{Hu \& Yoshida~\cite{hu-yoshida-2016}:} Generates state-indexed Java fluent channel classes ($C_{q_1} \to C_{q_2}$) with lightweight runtime linearity checks. Because C++ gRPC exposes every method on a single fixed stream class in all states, checking existing callers requires external contracts instead of splitting API types.
    \item \textbf{Session C~\cite{ng-yoshida-honda-2012-cc, ng-et-al-2012}:} Checks C/MPI and FPGA code against multiparty Scribble trees for distributed deadlock freedom, requiring programs to use custom \texttt{libsess} calls; we keep AST checking while leaving \texttt{grpc::} code unchanged.
    \item \textbf{Marques et al.~\cite{marques-et-al-2013}:} Checks \emph{unmodified} C calls to \texttt{mpi.h} using ghost contracts in Microsoft VCC/SMT ($4$ MPI programs, $256$--$429$~LOC). It proves stronger buffer and rank bounds at $3.9\%$--$4.7\%$ manual annotations and $3.7$--$11.4\,\mathrm{s}$ solver times; we trade memory/rank proofs for $0$ inline C++ annotations.
    \item \textbf{Coconut~\cite{alsubhi-et-al-2025}:} Encodes protocols in C++20 templates verified by a GCC-13 GIMPLE pass with runtime monitoring for aliasing pointers (cutting \emph{PillBox} NLOC from $389$ to $129$ and cyclomatic complexity from $90$ to $22$). We avoid C++20 rewrites, early IR lowering, and runtime checks, though Coconut's interprocedural summaries and alias tracking handle multi-function code better than our intraprocedural walker.
    \item \textbf{C/C++ Resource Checkers and Rust/Go Session Tools:} In the C/C++ ecosystem, Clang Static Analyzer's \texttt{StreamChecker}~\cite{clang-streamchecker} tracks path-sensitive \texttt{FILE*} typestates (\texttt{Opened}/\texttt{Closed}/leaked via \texttt{DeadSymbols}), and Meta Infer/Pulse~\cite{le-et-al-2022} scales interprocedural incorrectness-logic bug finding to large C++ codebases; however, neither reads external \texttt{.proto} contracts or Protobuf \texttt{oneof} payload progressions. For single-stream protocols in other systems languages, Jespersen et al.~\cite{jespersen-et-al-2015} use Rust's affine type system to enforce session protocols via wrapper channels, and Lange et al.~\cite{lange-et-al-2018} extract behavioural types from Go channels to check safety and liveness statically. C++ lacks affine move checking and exposes fixed \texttt{grpc::} stream classes, motivating external DFSM contracts over unmodified ASTs.
\end{itemize}

\subsection{Comparative Synthesis and Positioning Hypotheses}
\label{sec:rw-comparison}

Table~\ref{tab:related-work-comparison} separates external specification placement, C++ source edits, wrapper rewrites, inline annotation density ($0/100$~LOC inside C++ handlers, moving specification effort to $1$--$2$ \texttt{.proto} option lines per custom RPC or $0$ for default Level~1), and static vs.\ runtime checking. Because Mungo/StMungo and Coconut do not report inline annotation counts and we did not study developer error rates when authoring \texttt{.proto} options, the comparison captures structural intrusiveness rather than total specification effort. Section~\ref{ch:case-study} tests four claims:
\begin{itemize}
    \item \textbf{H1 (Zero C++ Source Edits):} Moving contracts into external Protobuf options checks synchronous C++ gRPC endpoints with $0$ C++ source edits and $0/100$~LOC inline annotations ($1$--$2$ \texttt{.proto} lines per custom RPC; $0$ for default Level~1).
    \item \textbf{H2 (Controlled Functional Accuracy):} On controlled test handlers covering Level~1 ordering and Level~2 payloads, our checker catches all planted sequence, variant, loop, and early-return faults with zero false alarms on conforming controls.
    \item \textbf{H3 (End-to-End Build Overhead):} End-to-end checking adds $O_{\mathrm{build}} < 1\%$ wall-clock overhead over plain \texttt{clang++ -fsyntax-only} compilation.
    \item \textbf{H4 (Unmodified Open-Source Specificity):} On unmodified OSS code without repo-specific heuristics (Section~\ref{sec:oss-baseline}), single-function checking achieves $\mathrm{Specificity} \ge 0.80$ on confirmed safe controls.
\end{itemize}
